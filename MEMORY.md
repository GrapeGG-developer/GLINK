## 1. Что такое GLINK

Android-приложение компании **GrapeScript** (разработчик — GrapeGG-developer).
Мощный аналог LocalSend: передача файлов, папок, текста, ссылок и «приколов»
между телефонами касанием NFC (зад-к-заду, «убийца NameDrop») и с компьютера
через веб-страницу. Плюс хаб-переходник («Линкер») ко всем приложениям компании.

- Пакет: `com.prilozhi.app`, подпись: `prilozhi/release.keystore` (alias `prilozhi`,
  пароль `prilozhi`; SHA-256 сертификата
  `32fdf77aa29b2b054b5c0eebf0a495eb424f8e84ec0fe55afe35c95ea95cf852`).
- Устройства владельца: Poco X3 Pro (MIUI 14 / Android 13) и Poco X8 Pro Max
  (HyperOS 3 / Android 16). minSdk 29, targetSdk 35, только портретная ориентация.
- Слоган в приложении: «Передача файлов! GLINK v{версия}».
- Нумерация версий: **ШЕСТЬ сегментов** (например 1.9.9.0.0.0), без суффиксов.
  ПРАВИЛО ВЛАДЕЛЬЦА: сегменты считаются как обычные счётчики 1..9 — после
  1.9.x идёт сразу 2.0.0.0.0.0, никаких «1.10» быть не должно.
  -STABLE/-BETA в имени версии. Эксперимент может помечаться бейджем TEST в UI,
  но не в versionName.
- Иконка приложения: `uploads/Group 2.png`. Логотип компании: `uploads/Logo2.png`
  (в приложении — оригинал напрямую на фоне, БЕЗ подложки/плашки).

## 2. Архитектура передачи (НЕ МЕНЯТЬ без явного запроса владельца)

- **Транспорт — только серверный релей** на собственном бэкенде владельца:
  `https://loltube-v8.onrender.com/glink/*` (Render, сервис `loltube-v8`,
  репозиторий GitHub `GrapeGG-developer/loltube-v8`, файл `glink-relay.js`).
- **NFC — только знакомство**: обмен session id + ключом шифрования (AID
  `F05052494C4F5A4849`, SELECT + CA hello `{v:3, id, name, has, s, k}`).
  Файлы по NFC НЕ передаются.
- **ЗАПРЕЩЕНО воскрешать**: BLE/GFCAS, Bluetooth RFCOMM, Wi-Fi Direct.
  Класс Gfcas удалён полностью, Bluetooth-разрешений в манифесте НЕТ и быть не должно.
  На устройствах владельца BLE/RFCOMM физически не заработали (MIUI/HyperOS) —
  это проверенный тупик, не предлагать снова.
- **Шифрование обязательно**, сквозное (E2E), формат GSENC1:
  заголовок `GSENC1` + salt 16 байт; ключ кадра = SHA-256(sessionKey || salt);
  AES-GCM, кадры 64 КБ `[4B len][IV12][ct+tag]`, завершающий пустой кадр.
  Открытый поток: `[4B len][manifest JSON {t, from, files[{p,s,m}], fun?, text?,
  link?}]`, затем на файл `[size:8][bytes][CRC32:8]`.
  Ключ передаётся только через NFC, фрагмент ссылки (`#k=`), код `glink://` или QR.
  Сервер хранит только шифротекст.
- Отправка: выбор (островок / Share Sheet `ACTION_SEND`/`SEND_MULTIPLE` на `*/*`)
  → шифрование в кэш-файл → загрузка частями по 4 МБ **тремя параллельными
  потоками** с докачкой (пропуск уже залитых частей), файлы ≤128 МБ сначала
  целиком в RAM. Приём: опрос `/glink/meta` до 4 минут → скачивание шифротекста
  по Range с докачкой в кэш → расшифровка потоком → `Downloads/GLINK`.
  После приёма — `POST /glink/done`, сервер удаляет файл.
- Пауза/Продолжить/Отмена — флаги в `State` + кнопки в уведомлении
  TransferService (foreground). WakeLock — только на время передачи (лимит 5 мин
  с продлением, отпускается на SUCCESS/ERROR).
- Срок жизни файла на сервере: базовый свип 1 час; отправитель выбирает
  **1 / 6 / 24 часа** (долгий тап по строке ссылки в островке), сервер хранит
  личный дедлайн (`.ttl.json`), эндпоинт `POST /glink/ttl/:s?h=N`.
- ПК → телефон: страница `https://loltube-v8.onrender.com/glink/send`
  (шифрование в браузере WebCrypto — зеркало GSENC1 на JS; файлы И папки
  целиком через `webkitdirectory`, структура сохраняется; после загрузки даёт
  браузерную ссылку `/glink/get/:s#k=…`, код `glink://receive?s=…&k=…` и QR).
  Телефон принимает: пункт «ПК ПРИЁМ» в островке (вставка кода), диплинк
  `glink://receive`, либо QR-сканер (долгий тап по островку, QrScanActivity,
  Camera2 + ZXing core 3.5.3).
- Публичная ссылка на скачивание в браузере: `/glink/get/:s`, ключ только во
  фрагменте `#k=`, расшифровка в браузере. Кнопка ссылки — ТОЛЬКО маленькая
  строка внутри раскрытого островка и только когда файл реально залит
  (`relayUploaded`). Никаких больших кнопок на главном экране.
- Прогресс друга: `POST/GET /glink/prog/:s` (получатель репортит %, отправитель
  в READY_SEND показывает «друг скачал: N%»).
- Авто-очистка кэша приложения: при запуске удаляются временные файлы передачи
  старше 24 часов.

### Известный серверный баг, уже исправленный (не повторить!)
Части файла на сервере пишутся АТОМАРНО (`имя.tmp-XXXX` → rename) и сборка идёт
под блокировкой `ASSEMBLING`. Прямая запись в финальное имя части ломала файлы
при параллельной загрузке (сборка хватала недописанные части: 7.3 МБ вместо 11).

## 3. Обновления приложения

- Фид: `https://raw.githubusercontent.com/GrapeGG-developer/GLINK/main/version.json`
  `{versionCode, versionName, apk, notes (';'-разделитель), size}`.
- Проверка — **только пока приложение открыто** (старт + цикл ~200 мс, гард от
  параллельных проверок). Фоновых проверок нет. Скачивание и установка —
  автоматически, без кнопки «Позже». Системное подтверждение установки — единственное.
- Пакет обновления качается в MediaStore `Download/GLINK` с **уникальным именем
  на версию** `GLINK-update-{versionCode}.apk` (одно и то же имя = MIUI/MediaStore
  подсовывает старый файл → бесконечный цикл обновлений; уже наступали).
  Авто-очистка старых `GLINK-update*.apk` при проверках (троттлинг 60 с), но файл,
  ждущий установки (`upd_keep_name`), не удаляется. Перед установкой проверяется
  полнота скачивания (размер совпал).
- **ПЕРЕД ПУБЛИКАЦИЕЙ ОБЯЗАТЕЛЬНО** проверить версию ВНУТРИ APK:
  `aapt2 dump badging` должен показать те же versionCode/versionName, что и фид.
  (Один раз фид обещал 1.9.0.0.0.0, а внутри был code 48 — получился бесконечный
  цикл обновления у владельца.)
- Панель обновления: тёмная, иконка приложения статичная, скругление 12dp,
  без анимаций и вращений; кнопка — прозрачный фазовый текст («скачивание…»,
  «установка…»); blur-behind окном на Android 12+.

## 4. Интерфейс (дизайн-система)

Фирменные цвета: фиолетовый `#8B5CF6`, зелёный `#22E39A`, фон почти чёрный.
Шрифты Roboto Thin/Light/Medium (bundled, `@font/glink_light` и т.д.).

- **Главный экран**: фон — BackdropView (медленно дрейфующие фиолетово-зелёные
  пятна настроения, скорость по состоянию; ERROR — красная вспышка; в покое
  рендер 20 fps ради батареи). Заголовок GLINK 52sp Light зелёным градиентом +
  слоган с версией. Логотип компании (оригинальный Logo2.png) без подложки.
- **Островок (IslandView)** — лицо приложения: справа вверху, отступ 18dp,
  ширина 58dp; раскрывается **только вертикально** пружиной (460/27, hCur не
  ниже 50dp), высота раскрытого тела — с запасом выше столбика пунктов
  (588/624dp, вью в разметке 730dp — иначе обрезается!). Жесты: свайп вниз —
  раскрыть, свайп вверх — свернуть, долгий тап (>600 мс) — QR-сканер.
  - Свёрнутый: круг, стрелки обмена (плавное покачивание ±9°), состояния:
    TRANSFER — кольцо прогресса + скорость/ETA/«уже/всего» под кружком;
    READY_SEND — фиолетовое кольцо заливки и «друг скачал: N%»;
    TAP — «Касание принято! Телефоны можно разносить» текстом ВНУТРИ островка;
    ERROR — перечёркнутые стрелки (НЕ восклицательный знак); CONNECTING — дуга.
    В готовности — мягкий авто-пульс кольцом раз в ~5 с. Никакой орбитальной точки.
  - Раскрытый: крестик-закрытие (→ приложение сворачивается `moveTaskToBack`),
    строка ссылки (тап — копировать, долгий тап — срок 1→6→24ч), пункты категорий:
    media, music, files (иконка — РОВНАЯ скрепка!), folder, apps, camera, text,
    contact, geo, затем **разделитель «ПРИЁМ»** (отступ 16dp + линия + подпись),
    `__pc` (приём с ПК), разделитель, `__close`. Иконки пунктов — рисованные
    вручную цветные глифы, **НЕ эмодзи**. Пункты въезжают каскадом после фона.
  - Касание работает только по телу островка; справа безопасная зона 90dp у
    текстов главного экрана. Оверлей-островок поверх других приложений УДАЛЁН
    по требованию владельца, не возвращать; SYSTEM_ALERT_WINDOW не запрашивать.
- **Разумная нагрузка**: островок в покое — 30 fps, на анимации/передаче — 60;

- **Предпросмотр перед отправкой**: карточки выбранного — миниатюра фото/видео

## 5. Приколы (GLINKFUN/1)

10 команд: LOGO, RAIN, SALUTE, VIBRO, DISCO, QUAKE, FLIP, SIREN, TORCH, PULSE.
Едут отдельным полем манифеста `fun` (НЕ текстом, строк «GLINKFUN/1» в UI быть
не должно). **ЖЁСТКОЕ ПРАВИЛО владельца: прикол — только ОДИН за передачу и
только отдельной передачей** (второй в очередь не добавляется, с файлами не
смешивается; в манифест уходит только первый — есть юнит-тест
`fun_onlyOnePerTransfer`). TORCH: задняя камера со вспышкой, при недоступности —
мигание экраном. SIREN: тоны + вибрация. VIBRATE и CAMERA разрешения в манифесте есть.

## 7. Сборка и публикация (рецепт)

Тулчейн живёт НЕ в рабочей папке, а в `/var/tmp/glink-tc` (JDK 17, Gradle 8.7,
SDK 35) — песочница его периодически сносит, тогда пересоздать:
скачать JDK17 (Adoptium), gradle-8.7-bin.zip, commandlinetools-linux-11076708;
`chmod -R +x` на bin каталоги (zip теряет +x!); sdkmanager: platform-tools,
platforms;android-35, build-tools;35.0.0.
Сборка: в `/home/user/prilozhi` записать `local.properties`
(`sdk.dir=/var/tmp/glink-tc/android-sdk`), env JAVA_HOME/ANDROID_HOME/PATH, затем:
`gradle testReleaseUnitTest assembleRelease` + `gradle lintRelease` +
`apksigner verify` + **`aapt2 dump badging` (проверить версию внутри!)**.
**ТЕСТЫ ОБЯЗАТЕЛЬНЫ при каждом релизе** (JUnit, сейчас 8 тестов в
`GlinkUnitTest`), lint — 0 ошибок.
Публикация: APK → `/home/user/GLINK.apk` + `glink-site/GLINK.apk`, version.json
с реальным размером, коммит через GitHub Git Data API (токен владелец присылает
в чате; **токены/ключи НИКОГДА не писать в файлы и не выводить в чат**; после
работ советовать владельцу перевыпустить). Верификация фида — через Contents
API (raw.githubusercontent отстаёт из-за кэша). После сборки удалить
`app/build`, `.gradle` и т.п. — рабочая папка < 128 МБ / 10k файлов.

## 9. Характер и договорённости с владельцем

- Владелец — GrapeGG; общение на русском, живо, с эмодзи в меру; он нетерпелив
  к багам и любит, чтобы всё проверялось тестами («ТЕСТЫ ОБЯЗАТЕЛЬНО»).
- Новые функции — предлагать списком и делать выбранное, не выдумывать лишнего.
- Скриншоты от владельца — главный источник правды по UI: сборка идёт «вслепую»
  (эмулятора/устройств у ИИ нет; есть `ui-preview.svg` — рендер-макет главного
  экрана по реальным размерам из кода, сверяться перед релизом).
- Интерфейс должен быть ЖИВЫМ (анимации, пульс, дрейф фона), но без перегрузки
  телефона; все анимации плавные, пружинные, без рывков и «кривого кручения».
- Секреты (GitHub PAT, Render API key) владелец присылает в чате. Их нельзя
  сохранять в файлы репозитория/памяти и нельзя выводить обратно в чат ни в какой
  кодировке. Напоминать владельцу перевыпускать ключи после использования.
